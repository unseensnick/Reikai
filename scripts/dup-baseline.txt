# kept on purpose. One per line: file A, file B, hash of the normalised tokens (tab-separated).
# Regenerate with: pwsh scripts/dup-check.ps1 -UpdateBaseline, and say in the commit why a new one
# is kept. -UpdateBaseline keeps this comment header as written: add a reason below for a new pair
# group.
#
# Why each pair group is kept:
# - Backup models (BackupManga/BackupNovel, custom info): the
#   proto shapes share field numbers on purpose; pinned by BackupCustomInfoConformanceTest and
#   BackupDatesConformanceTest.
# - DownloadStore / NovelDownloadStore: Reikai's persisted/replacePersisted pair, written into each
#   engine's store (the manga one as an RK island) for MergedDuplicateDownloads; pinned by
#   MergedDuplicateDownloadsTest over both types.
# - NovelListApi / RanobeDbApi: tracker API client scaffolding (auth, request and paging setup).
# - NHentai / NHentaiNet: the wrapper and the native source for one site share a metadata contract;
#   each body is already a call into NHentaiApi.kt.
# - AsmHentai, HentaiFox, Koharu: Reikai's own wrappers with no upstream file, kept alike because the
#   wrapper contract is the same override set, each body a shared call.
# - MangaType / MangaLewd: Komikku-shaped helpers, kept in upstream shape so a re-port diffs cleanly.
# - EightMuses / HentaiNexus (and the later TachiyomiSY gallery wrappers): the wrapper contract's
#   override boilerplate (layered details update, URL-import search), each body already a shared call.
# - Workers (EHentaiUpdateWorker, MangaDexSyncWorker, NovelUpdateWorker, TrackerRefreshWorker):
#   WorkManager setup, the foreground notice and constraints.
# - MangaViewModel / NovelDetailsViewModel / NovelLibraryViewModel / NovelReaderViewModel /
#   MigrateNovelUseCase: DI
#   constructor lists and the details engine twin behind the shared details contract.
# - CombineLocalVolumes / NovelDetailsViewModel: a DI constructor list, over the token threshold once
#   the series lock and the file journal joined it.
# - MigrateMangaUseCase / MigrateNovelUseCase: engine twins, pinned by MigrateEngineConformanceTest.
# - Update-error interactors and repositories: engine twins over separate tables, pinned by
#   UpdateErrorConformanceTest.
# - CustomMangaInfo / CustomNovelInfo repositories: engine twins, pinned by ResetEntryInfoConformanceTest
#   and BackupCustomInfoConformanceTest.
# - Group stitchers and chapter aggregation: engine twins, pinned by MergedTrunkConformanceTest and
#   MergedCountConformanceTest.
# - PropagateTrackerLinks / PropagateNovelTrackerLinks: both forward to the handOutGroupTrackers kernel.
# - RemoveMangaFromLibrary / RemoveNovelsFromLibrary: pinned by EntryLibraryRemovalConformanceTest.
# - Entry, library, migration and recents adapters, TachiyomiNovelSource / IReaderNovelSource:
#   adapter forwarders, one per engine or source kind, each the only seam to its side.
# - Preference holders and settings screens (ReikaiLibraryPreferences, ReikaiRecommendationPreferences,
#   EntryDisplayPage, ReikaiLibrarySettings, SettingsMangaReaderScreen, SettingsRecommendationsScreen):
#   preference declarations and settings DSL lists.
# - SavedSearchDialogs / FeedDialogs: dialog scaffolding around different fields.
# - Novel repository implementations: one-line query-and-map methods (by id, by ids, as a flow) over
#   different tables.
