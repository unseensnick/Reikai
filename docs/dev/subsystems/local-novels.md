# Local files: local novels, import and EPUB export

## Purpose

Lets a reader bring their own books and comics in and take novels out. EPUB books in the `localnovels` storage folder are a novel source of their own, beside manga's Local source; an import screen copies picked or shared files into either folder; and any novel's chapters on the device can be written out as an EPUB.

## How it works

**The EPUB kernel** (`reikai/novel/local/epub/`) is plain Kotlin over an `EpubArchive`, which reads several zip entries in one pass (`ArchiveReader.readEntries`, since libarchive finds an entry only by scanning from the first). `EpubBook.parse` reads the package: metadata (with Calibre's and EPUB 3's series and position), the spine, the cover (EPUB 3 property, EPUB 2 meta, then an image named or id'd as one), and the table of contents, the EPUB 3 nav before the EPUB 2 NCX, and of the NCX only its `navMap`; an entry that names only an anchor (`#ch2`) points into the previous entry's file. Tags are matched by local name, since packages spell `opf:item` and `item` alike.

`EpubChapters.list` reads the book as one stream in spine order and cuts it where the contents point (`EpubCut`): a chapter runs from its cut to the next, across files, so a file the contents skip continues the chapter before it and a file holding several chapters is divided at their anchors. A place the contents list again further on is dropped (as Tsundoku drops a repeated entry), since a second chapter at one key could never be opened, and what it would have started runs on in the chapter before it. Whatever comes before the first entry opens the first chapter. With no contents, each file is a chapter, and a book that is a single file is cut at its top-level headings. A chapter with under 100 characters and no picture joins the next, named for both ("BOOK ONE - CHAPTER I"), except in a book Reikai exported (its identifier starts `urn:reikai:`, `isReikaiExport`), where every entry is a real chapter. A Gutenberg caption in front of a chapter name is dropped (`cleanTitle`), unless the words before the name number or name a chapter themselves ("Chapter 45 - Showdown! Part 2").

`EpubChapters.render` cuts each file the chapter covers (`keepFrom`, `keepUntil`; an anchor that opens its element stands for the element, `lift`), turns an SVG that only frames a picture into an `<img>` (the renderers drop SVG), keeps links only within the chapter, keeps an embedded `data:` picture as it is, drops a picture on the web (a local book reads nothing from the web), and points each other `<img>` at the book's own address for it (`LocalNovelSource.pictureAddress`: the series, the book's file name and the entry's zip path, plus the book's modified time so the image cache never serves a replaced book's picture). Nothing is read for a picture until the reader shows it, so no picture is too big: both renderers load the address through the chapter-picture fetch (`fetchNovelImage`, `isNovelImageAddress`), which reads the entry from the book (`LocalNovelSource.picture`) and stores it in Coil's disk cache like a fetched picture, so the text renderer decodes it at display size and reads a tall one in slices from that file, and the WebView serves it from its app-answered address with no file access. An address resolves only for a chapter of the local source (`NovelImageRequests.localPicture`), only to a series directly in the folder (`isChildName` refuses `..` and separators) and one of its own books, and only to an entry of that book. Linked and inline stylesheets come along without fonts, imports, colours or backgrounds, so the reader's theme wins while indents and alignment stay; a stylesheet picture is inlined as `data:` through `inlinedImageAddress`, under the cap downloads use, when the manifest declares it an image (`EpubBook.imageType`), since neither renderer fetches what a stylesheet names. Scripts and event handlers are left to the reader's shared sanitizer (`NovelHtmlUtils`), so a local book follows keep-embedded-JS like any source.

**The source** is `LocalNovelSource`, id `local`, handed to `NovelSourceManager` as a built-in through `ReikaiBindings.providesBuiltInNovelSources`. Each folder under `localnovels` is a series and its EPUBs are its volumes; a loose EPUB is a series of one. A series reads its volumes by their series number when every readable volume carries one, else in natural name order, ties going by name (`inVolumeOrder`, the order import numbers copied files in too). A volume is labelled with its series number, except a Reikai export's, whose number is where its run starts, so it takes its place in the series instead (`volumeLabel`). Browse still picks a series' title and cover from its first volume by name, since ordering by number would read every volume's package. A `details.json` (manga's `MangaDetails` schema) or a `cover.*` picture in the folder (`localCover`, the rule manga's local source reads too) wins over the books; otherwise the first readable book's cover is copied once into app storage. A cover set from the cover viewer is written as that `cover.*` (`LocalNovelSource.writeCover`), in the library or not, through `writeLocalCover`, the kernel manga's `LocalCoverManager.update` writes through too: from empty, with a `.nomedia` beside it, and the series' copied book covers are deleted then; a loose EPUB has no folder, so it takes an ordinary custom cover. Browse and search read only each book's package, cached per file version; a book's chapter list, which parses every chapter file, is cached only for the few novels being opened. A local chapter's text never goes in the chapter text cache, since a file replaced under the same path would keep showing its old text.

A chapter's path (`chapterPath`) names the series, the volume file and the chapter's `EpubChapterKey`: the file and anchor its contents entry points at, or for a single-file book cut at its headings, the heading's text and how many headings before it share that text, never its place in the spine or among the headings. Each part is percent-encoded, so a `::` in a folder or file name reads back. A book updated with a chapter added partway through keeps every other chapter's path, so the sync hands no read state to the wrong chapter; renaming a volume file gives its chapters new paths and loses their history, as renaming a manga local chapter does. A refresh leaves out only a volume that is protected or not an EPUB; any other failure to open one fails the refresh (`readableVolumes`), since a list missing a volume would delete its chapters' read state. Its web address is blank, which hides WebView, Share and Copy link.

**One lock per local series, both types** (`LocalSeriesLocks`, keyed by type and lower-cased folder name). A refresh holds it from its listing to its row write (`UpdateMangaFromRemote.underSeriesLock` for a local manga, `LocalNovelSource.locked` through `refreshNovelFromSource` for a novel), and so does every change: combine and split with their Undo, Delete volumes, Organize files and its replay, an import into a series folder, and a relink; so a listing taken before a move can never write rows after it. Naming a series takes every folder its group lists across (`LocalGroups.closure`), retaken whole if the group grew while waiting. A holder names every series it will touch up front and takes the keys in one sorted order, which is the deadlock proof; the lock is reentrant by coroutine context, so a move's own relist inside it waits on nothing, and a nested ask for a key the holder did not name is refused (`IllegalStateException`) rather than left to hang. Covers are written outside it. The `insertOpenedNovel` path parses under the lock and syncs after it; a combine between the two leaves phantom rows and a refused Undo, no loss.

**A removed local chapter keeps its reading state** (`ChapterTombstoneRepository`, the `*_chapter_tombstone` tables with their sessions). When a local refresh confirms a chapter's file gone from a trusted listing of its folder, the sync's transaction captures the row's read, bookmark, progress, length, history and sessions under the owner and url; a chapter arriving at that url, the same url in another letter case, or the one removed chapter it alone shares a recognized number with revives it (`tombstoneRevivals`). Every write onto a key already held and every revive folds by one rule (`ChapterTombstoneFoldConformanceTest`: read and bookmark stick, the larger progress and times, the earlier fetch date, the union of sessions). The kept state goes where its volume goes. Organize files, the relink and an older build's Rename files replay read the series' chapter addresses, a row's or a kept state's, inside their own transaction (`LocalChapterMoveRepository.organize` and `rename`), so no caller can forget a half. A combine, a split and their Undo find each moved volume's chapters, rows and kept states alike, inside their transaction (`regroup`), so a chapter put back since the last listing, or first listed after the move, goes with its volume; a transaction settles only the keys it wrote, never the owner's whole table. A kept state is dropped only where the user put new files on purpose: Delete volumes forgets under the volumes it deleted itself, never one it could not find (a failed query reads as absent), before and after the relist that removes their rows (the listing removes rows, never the delete itself). A grouping moves no address, so the kept state at one is that file's own. A newer copy of a book the user replaces on import is the same book by the import's match, so its kept state stays. Backups carry the kept states at field 704 on both entry messages, read after the chapters so a capture between the two reads lands in both lists; a restore folds them in and settles them and the restored chapters against the rows.

**A series folder renamed outside the app** (`LocalSeriesRelink`) fails its refresh, since its address is the folder name. The details screen then offers the folders in the local root's trusted listing that hold every chapter file the series' rows name (`relinkCandidates`, case-blind, folders another entry already holds left out), and never picks one: the user links it (`RelinkSeriesDialog`), and the relink re-checks under the lock on both names that the old folder is still absent from that listing and the picked one still matches, then runs Rename files' row step. Whether the folder is missing is read from the root's trusted listing, never a document's own query; a root that cannot be listed whole offers nothing. A loose novel book carries nothing but the name that changed, so it has no candidates.

**Grouping moves no file.** A chapter's address always names where its file is. `local_volume_owner` says which series lists a volume of another folder (a manga volume folder, a book, a folder's loose chapters as `''`, or the whole folder as `'/'`); a volume's owner is its own row's, else its folder's whole row's, else the folder itself, so no volume lists under two series (`LocalGroups`). Both sources list a series' own folder and then the volumes it holds, and Browse hides a folder another series holds whole. A volume's key in a group is its own name in the owner's folder and `folder/name` elsewhere (`localGroupKey`), which `local_volume` and the picked chip are keyed by. Combine, Add volumes and Split write only these rows, the chapters' owner and the volumes' saved order and names, in one transaction (`LocalChapterMoveRepository.regroup`); a split-out series has no folder of its own (a self row) until it is organized. An Undo is refused once a later change replaced the rows it wrote. Backups carry the rows a series holds at field 705 on both entry messages, and its remembered volume chip at 706, in a pass of their own so a series with no chapter rows keeps its grouping.

**A member folder gone missing never stalls its group.** A folder (or loose book) the group lists that the local folder's trusted listing no longer holds is left out of the listing, and both syncs keep its chapter rows as they are (`LocalGroups.missingMembers`, `LocalChapterTombstones.held`); the series' own folder missing still fails the refresh, for the series relink. The details screen names each missing volume above its chapters, and a tap offers three choices, never one made for the user: a folder holding the same chapter files (the series relink's content match, `memberCandidates`), any folder or book inside the local folder (`memberChoices`), each leaving out folders another series lists or holds; or Remove from series. Linking rewrites every row keyed by the old name through the row step Organize files writes, owner rows keeping their place in the group (`relinkMember`), under the lock, refused unless the series holds the folder whole. Removing is one regroup that hands the member's rows, kept states and saved volume rows back to its own series, as a combine's Undo does, so its reading state is there when the folder returns (`removeMember`).

**Loose files** (manga only, ⋮ -> Reorder volumes): the chapter files loose in a manga's own folder show as one volume (the default, labelled Extras and renameable), each as a volume of its own (keyed by its file name, as a volume folder is by its own, so it takes a name and a place), or in no volume, which leaves the whole series one flat list without headers or chips (`LooseFiles`, `ChapterVolume.under`, stored per series in `local_manga_loose`, backed up at `BackupManga` 707, carried by a folder rename). It rules only the series' own folder: another folder's loose chapters, a series combined in whole, stay one volume under that folder's name and cover (`localVolumeKey`, `LocalSource.volumeCover`). The details screen, the reader's chapter sheet and the source's order follow it; Split out, Delete volumes and Organize files act on the loose files together, as their files sit.

**Organize files moves them, on the user's word.** It replaces Rename files: from a fresh listing under the group's lock it plans the rows first (addresses through `organizedUrl`, the series' owner rows dropped, a folder it held whole re-pointed at the new name) and then one `DocumentsContract` rename or move per document through the storage gateway (`rename`, `moveTo`), every volume named `<series> - <label>` in the series' folder, which reads back as its label (`organizedLabel`). The plan is journaled first and each step noted as it lands, the rows' note inside the rows' transaction (`LocalOrganizer`). A step that fails puts back the steps before it by the same path, last first; a put back that fails too keeps the journal row and refuses the group's folders until it resolves: a retry in this process takes the row up again under a hold its own block lets through (`LocalSeriesLocks.repairing`), after a wait that doubles from two seconds to at most five minutes, and the next start's replay does the same; each first reads whether the cut step landed (old name gone and new one there, or the reverse), and when it cannot tell, waits for the next try. Undo runs every step reversed. It is offered only where the provider flags both move and rename, and never moves the tree root; every Also organize files tick (Combine as volumes, Add volumes, Split out, Edit info, Reorder volumes) starts unticked and is hidden where the storage cannot move. A folder another series lists volumes of keeps its name. The `.moved-` set-aside rule stays for the download merge and for a folder Organize made and its putting back emptied.

**Language.** A local source's own language is the placeholder `other`, so a local series' language is read from its files and the library, search, group by language, Statistics and export read that instead (`entryLanguage`, `localLanguage` in `domain/.../EntryLanguage.kt`, which keeps a region only where sources split by it). A novel's is written to `local_novel_language` by series path each time `parseNovel` reads it, `details.json` over the EPUB's `dc:language`, and stored as that code, so a three-letter tag reads as its two-letter one and `mul` as Multi (`all`). It is backed up on the novel (`BackupNovel.language`) and restored into the table, since a restored novel with chapters is not read again until a refresh. A manga's rides in its `memo` (`reikai:language`, backed up with it), from ComicInfo `LanguageISO`, and a legacy `details.json` language survives its conversion to `ComicInfo.xml`. A merged series searches and groups each member by its own language, not its source's, since every local series of a type shares one source. `LocalSeriesLanguageMigration` reads every local series in the library of both types once on upgrade, through each local source's own details read, so an existing library gets its languages without a refresh. Export writes the entry's language as the book's (`bookLanguage`), with Multi as `mul`, so a re-imported copy groups under Multi again.

Local is a source state like manga's (`EntrySourceState.Local`): no download controls, no browse link, left out of the migration source list, never disabled, and its chapters count as on the device (the novel `downloadedChapterIds` kernel, as manga's), so the downloaded filter, Downloaded only, search and word count include them. `NovelDownloadedTexts` reads a local chapter's text from its book.

**Import** (`LocalImport`, `LocalImportScreen`) serves both types. A picked, opened or shared file is read for a preview: an EPUB through the kernel (fixed-layout books suggest manga), a comic archive for its ComicInfo series and writer and its first page. The kind comes from the name, else the provider's MIME type, else the archive's contents (`EpubBook.looksLikeEpub`, else a page by `ImageUtil.isImage`), and a copy without an extension gets one. A file a provider streams through a pipe is read from a copy in the cache, since it cannot be mapped. A file's name is the provider's, made safe as a file name. Files group by type and series key (`groupKey`), and a group is named after its series, even a lone EPUB volume, so it lands where its siblings do. An Open with or Share takes only `content:` URIs, judged per file by the type or name its provider gives; one that arrives while the import screen is open joins its picks (`ImportHandOff`) rather than replacing them. Import copies each group into the folder whose name matches its series by `groupKey`, or a new one, in `local` or `localnovels` (numbered when a new series gets several files, skipped when a file of that name and size is there), then stores and favorites it through each type's batch add: `insertOpenedNovel` and `NovelLibraryAdder.addToBatch` for novels, `NetworkToLocalManga`, `UpdateMangaFromRemote` and `MangaLibraryAdder.addToBatch` for manga. An EPUB joining a series is matched to the books already there by its package identifier and series number (`bookIdentity`, `newerCopiesOf`): one with the same identity at another size is a newer copy, and the import waits until the user says Replace, Keep both or Skip, with nothing picked for them, since a replaced copy keeps the old one's read progress and one kept beside it lists every chapter twice. Categories are asked once per type when the batch rule says so. The copy runs on the app scope.

**Export** (`EpubWriter`, `NovelEpubExportWorker`) writes EPUB 3 with an EPUB 2 NCX beside the nav. `mimetype` is stored first; each chapter is well-formed XHTML with its `data:` pictures, and a local chapter's book pictures (read through `ExportChapter.localPicture`, the same gated read the reader uses), written once each as files, web pictures and anything that runs dropped, and a heading added only when the chapter does not open with one. A chapter's file is named by a hash of its source chapter's address, never its place, since an imported book keys each chapter by its file: a re-export that leaves out chapters deleted after reading keeps every other chapter's key, so no read state moves. A link within the chapter stays when `anchorTarget` finds its target, as both readers find it (an id, an old-style `name` or an `xml:id`, as written or percent-decoded), and a target without an id gets the one its link names; any other relative link keeps only its text. The metadata is what the import reads back: title, author, the artist as an illustrator contributor, the status in a `reikai:status` meta, genres as subjects and the description as paragraphs, so a source novel exported and imported keeps its details. A run of chapters is written as a volume of a series named for the novel, placed at its first chapter's position, in both EPUB 3's collection and Calibre's metas, so several runs imported together read in order; a whole novel carries no position. The worker exports the chapters on the device in reading order (`NovelDownloadedTexts.chaptersOf`), a run of them if asked, to one file or, for a library selection, one file per novel in a folder. A novel's details are the library's, Edit info applied (`withCustomInfo`). A folder export names each book by `EpubFileNames`, cut so `.epub` always fits and numbered for a second novel of one title, matched ignoring case. A book exported again is written beside the earlier copy and put in its place through the storage gateway's `replace` (`writeBookNamed`), so a failed export or a refused rename leaves the earlier one. Exports run one at a time, each its own work, so cancelling or failing one leaves those queued behind it; their notices leave a novel unnamed under Hide notification content or the adult switch (`hiddenEntryIds`). Chapter text comes through `NovelDownloadedTexts.storedHtml`, the read search and word count use, and chapter markup through the reader's own prune (`NovelHtmlUtils.sanitizeForRender`) before the book's extra drops. The cover is loaded the way the library draws it (custom, a local series' `cover.*`, cached or fetched) and written as JPEG, or PNG when it has transparency. A file the picker named is built whole in the app cache first and only then copied over it from empty (`writeBookOver`, through `openTruncatingOutputStream`, since a document provider takes plain "w" as write in place, and a document cannot be renamed over), so a failed or cancelled export leaves the file it would have replaced as it was; one the picker newly created, still empty, is deleted, and a copy that fails partway deletes the file, so no half book is left behind.

## Invariants and traps

- **A regex here must compile on Android's ICU engine, not only the JVM's.** A bare `}` that Java accepts made `EpubChapters` fail to initialise on a device while every JVM test passed; escape every brace.
- **Only an encrypted chapter file means DRM.** Most books carrying `encryption.xml` only obfuscate fonts.
- **The category dialog dismisses before it confirms.** Answers already given survive a dismiss; a new import resets them.
- **A test chapter needs real length.** Under 100 characters it is read as a part title and joined to the next.
- **The local source's text arrives decoded.** The EPUB reader decodes its XML and HTML already, so entity decoding happens in each scraping adapter (`withDecodedDetails`, `withDecodedText` for a chapter), never in the shared `toNovel` or `toNovelChapter`, or a description or chapter title that spells `&amp;` loses it.
- **Local chapters are on the device but have no download file.** Anything that reads stored text for a local chapter goes through the source, never `getChapterText`.
- **A holder of the series lock names every folder it will touch up front.** A nested ask for a key it did not name throws rather than waits; a move that creates or renames a folder names the new name too, as storage spells it.
- **A failed document query answers no to every question.** A picked folder's `isDirectory`, `isFile`, `exists` and `length` all read false or -1 when the provider hiccups, so a guard asks the question whose "no" refuses (`deleteFile` asks `isFile`, a marker file is `isFile` and dot-named), never the one whose "no" permits.
- **A `.moved-` folder is a moved original set aside, not a chapter.** Every listing skips dot-named entries, and no code deletes one: a picked folder's delete takes everything in it, and its listing can hide the same file at every reading, so no listing proves a folder empty.
- **A folder is new only when two readings say so.** A new folder (Organize's, an import's) is made with `createNew`, which refuses a name the listing holds and a folder its own query finds: a query that fails reads as "absent", a listing can leave a folder out, and the create that follows hands back the folder already there, which a failed move would then delete as one it made.

## Decisions

- **Loose files is not offered for novels.** In a local novel every book is a volume, whether in a series folder or loose as a series of one, so a novel has no loose files to show any other way.
- **A missing member is never relinked or removed for the user.** A folder holding the same file names is evidence, not identity, as for the series relink; the screen asks.
- **Delete volumes never deletes chapter rows itself.** The relist's own sync removes them, as for any file gone, and the kept state it captures is forgotten after it; a second row-delete path beside each type's sync is what the content layer forbids.
- **A newer copy replaced on import keeps the old book's kept state.** The import's own match says it is the same book, and the sync revives a returning chapter by its address; a different book at the same name is not something the import can express.
- **The relink matches folder contents, not a marker file.** A marker needs a table and a write into the user's folder on a read, and no series that predates it would carry one; a renamed folder with a chapter also deleted matches nothing and is left alone, which is safe.

- **Files are copied in, not linked.** A picked document's permission does not outlive the app; void if a persisted tree grant is used instead.
- **A book is read from its zip each time, not unpacked.** Deleting the file removes the series and nothing is stored twice; void if reading a chapter from a large book becomes slow.
- **A local chapter's pictures are read from the book by address, never inlined** (as Tsundoku serves an EPUB's pictures). Inlined, a picture costs its base64 in the chapter text and must sit under a cap, and the illustrations a light novel carries run past it and vanished; one path for every size keeps both renderers loading the same way. A broken reference to an entry the book lacks shows the failed picture box instead of vanishing. Stylesheet pictures stay inlined under the cap, since neither renderer fetches them; void if one does.
- **EPUB export is novels only.** Manga's offline copy is the CBZ Mihon already writes, and an image-only EPUB of a comic serves few readers; void if users ask for comic EPUBs.
- **Export writes only what is on the device.** Fetching during an export would meet rate limits and challenges with nobody watching; the dialog offers the download instead.

## Extending

A new book format: give `LocalImport.kindOf` its name, type and contents test, and a source that reads it. A new metadata field: read it in `EpubBook.readMetadata` and map it in `LocalNovelSource.parseNovel`.
